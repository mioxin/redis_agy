# Руководство по профилированию и диагностике производительности (pprof)

> **Микросервис:** Courier Location Service  
> **Инструменты:** `net/http/pprof`, `go tool pprof`, `go tool trace`, CLI-клиент нагрузки `cmd/client`

---

## 1. Введение

В проекте интегрирована стандартная подсистема профилирования Go (`net/http/pprof`), позволяющая исследовать работу сервиса в двух режимах:
1. **Профилирование работающего сервиса под реальной или синтетической нагрузкой** (через HTTP-эндпоинты и CLI-клиент).
2. **Профилирование изолированных бенчмарков** (без необходимости запуска Redis и сервера).

Управление профилированием осуществляется через переменные окружения:
- `PPROF_ENABLED=true` — включает эндпоинты `/debug/pprof/*` (по умолчанию включено).
- `BLOCK_PROFILE_RATE=10000` — частота семплирования блокировок в наносекундах (0 = выключено).
- `MUTEX_PROFILE_FRACTION=5` — доля семплирования конкуренции за мьютексы 1 из $N$ (0 = выключено).

---

## 2. Способ 1: Профилирование работающего сервиса под нагрузкой (Рекомендуемый)

Этот метод позволяет снять реальные профили CPU, аллокаций памяти, конкуренции мьютексов и блокировок во время активной обработки запросов.

### Шаг 1. Запуск сервиса
В первом терминале запустите сервис:
```bash
go run cmd/server/main.go
# Сервер слушает на :8080, pprof активен по адресу /debug/pprof/
```

### Шаг 2. Генерация нагрузки через встроенный CLI-клиент
Во втором терминале запустите многопоточный CLI-клиент для создания непрерывного потока запросов (например, 10 параллельных воркеров, 5000 запросов):
```bash
go run cmd/client/main.go -url=http://localhost:8080 -threads=10 -requests=5000 -interval=10ms
```

---

### Шаг 3. Сбор и анализ профилей

В третьем терминале выполните сбор нужного профиля во время генерации нагрузки:

### 1. Профиль процессора (CPU Profile) с интерактивным Web UI (Flame Graph)
Сбор 10-секундного семплирования CPU и автоматическое открытие веб-интерфейса в браузере:
```bash
go tool pprof -http=:6060 http://localhost:8080/debug/pprof/profile?seconds=10
```
> **Что смотреть в Web UI:** Вкладка **VIEW → Flame Graph**. Выявляет функции, потребляющие больше всего процессорного времени.

Сохранение в файл для повторного анализа:
```bash
curl -s "http://localhost:8080/debug/pprof/profile?seconds=15" -o cpu.pb.gz
go tool pprof cpu.pb.gz
# В интерактивном CLI: top20, list LocationHandler, web
```

---

### 2. Профиль памяти и кучи (Heap Profile)
Снимок состояния кучи в текущий момент:

#### А. Анализ активного потребления памяти (поиск утечек памяти):
```bash
go tool pprof -http=:6060 -inuse_space http://localhost:8080/debug/pprof/heap
```

#### Б. Анализ суммарного количества созданных объектов (поиск источников GC Churn):
```bash
go tool pprof -http=:6060 -alloc_objects http://localhost:8080/debug/pprof/heap
```

---

### 3. Профиль блокировок и конкуренции за мьютексы (Contention Profiling)

#### Конкуренция за мьютексы (`sync.Mutex` / `sync.RWMutex`):
```bash
go tool pprof -http=:6060 http://localhost:8080/debug/pprof/mutex
```

#### Ожидание на каналах (`urgentQueue`) и семафорах воркера:
```bash
go tool pprof -http=:6060 http://localhost:8080/debug/pprof/block
```

---

### 4. Проверка утечек горутин (Goroutines Stack Dump)
Текстовый дамп всех запущенных горутин:
```bash
curl -s "http://localhost:8080/debug/pprof/goroutine?debug=1" | head -n 40
```
> Позволяет убедиться, что число горутин после нагрузки возвращается к базовому значению и отсутствуют зависшие горутины.

---

### 5. Трассировка планировщика рантайма (Execution Trace)
Запись событий планировщика Go, фаз работы Garbage Collector и сетевых ожиданий:
```bash
# Сбор 5 секунд трассировки
curl -s "http://localhost:8080/debug/pprof/trace?seconds=5" -o trace.out

# Интерактивный просмотр таймлайна в браузере
go tool trace trace.out
```

## 3. Способ 2: Сбор профилей из автономных бенчмарков

Если требуется изолированно исследовать только обработчики или кэш без внешних зависимостей:

```bash
# 1. Сбор профиля CPU бенчмарка Fast Path:
go test -bench=BenchmarkLocationHandler_CacheHit -cpuprofile=cpu_bench.prof -benchmem ./internal/handler/http/

# Анализ в pprof CLI:
go tool pprof cpu_bench.prof
(pprof) top10
(pprof) list GetCourierLocation

# 2. Сбор профиля аллокаций памяти:
go test -bench=BenchmarkLocationHandler_Parallel_SLA -memprofile=mem_bench.prof -benchmem ./internal/handler/http/

# Анализ источников аллокаций:
go tool pprof -alloc_space mem_bench.prof
```

## 4. Шпаргалка команд интерактивной консоли `pprof`

| Команда | Описание |
|---|---|
| `top 15` | Топ-15 функций по потреблению ресурсов (`flat` / `cum`) |
| `top -cum` | Сортировка по кумулятивному времени (включая вызываемые функции) |
| `list <FuncName>` | Построчный листинг исходного кода функции с замерами на каждой строке |
| `web` | Экспорт и открытие графа вызовов в браузере (требуется `graphviz`) |
| `peek <FuncName>` | Анализ caller / callee (кто вызывает функцию и кого вызывает она) |
| `help` | Справка по доступным командам |
| `quit` | Выход из консоли pprof |
